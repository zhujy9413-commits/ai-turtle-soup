页面交互待确认验收实施顺序依据

一局的主线

选题与配置→汤面发布→推理（含系统处理中）→结束结算→固定揭晓→个性化复盘或明确降级收尾→已完成并回选题

系统处理是推理中的暂态，不把每一次模型调用变成新页面。计时、次数、结束原因与整局完成状态由程序管理。

3 个主页面、3 个弹层

P1

选题与开局

选一道汤，确认规则后开始。

内容
题名、推理难度、恐怖强度、必要内容提醒、已玩标记；可筛选或随机；选中后在同页展开时长和次数设置。
操作
开始游戏、查看玩法；随机结果仍需点击开始。
状态
没有符合条件的题目／仅剩已玩题时明确提醒；载入失败允许重试。
边界
不展示本格／变格、汤底、关键因果、模型配置。首次进入可跳过教学；加载完成即可进入，不为开场动画延长等待。
P2

局内推理

读汤面、提问、获取提示并还原故事。

内容
题名、剩余时间、剩余次数；顶部可展开的完整汤面；按时间排列的提问、四词回答、澄清、提示和系统消息；底部提问输入区。
操作
提交问题、获取下一层提示、提交还原；规则、音量、问题反馈入口保持可见；查看汤底为次级操作。
状态
汤面载入／等待主持／澄清待改写／提示发布／待核验／断线恢复；处理中禁用重复提交。
边界
两段模型等待合并显示“主持人正在判断，计时已暂停”；不展示范围字段、事实编号、模型名或Token。单人不另建多人讨论区。
P3

揭晓与复盘

完整理解故事，结束这一局。

内容
结束原因、固定汤底、按时间线的因果解释；本局真实问答记录；个性化复盘或明确标注的固定讲解降级；可跳过的反馈。
操作
回看记录、反馈问题；收尾完成后返回选题，开始另一局。
状态
揭晓发布中／复盘生成中／复盘完成／复盘降级；已完成和中断分开记录。
边界
完整发布复盘或明确完成降级收尾后，才将本局标为完全结束；反馈不强制。回选题只是单人原型的呈现，完整内测版仍按既定规则回原房间。

弹层

弹层入口内容提交／确认关闭／取消
提交还原游戏页独立按钮展开长文本输入；可保留未提交草稿；明确提醒：未通过的有效还原消耗一次剩余次数。与正式问题分开提交；不因普通问答里说中答案自动通关。取消不扣次数；处理中不允许重复提交。
玩法说明选题页和游戏页规则图标解释汤面／汤底、四词含义、澄清、提示、还原、共享次数和冻结规则；局内可随时重看。关闭后回原位置，不清空输入。阅读期间正常计时。
提前揭晓确认游戏页次级“查看汤底”提示该操作会结束推理并公开答案。建议二次确认后进入揭晓复盘，结束原因为“主动揭晓”。取消后继续推理，不扣次数、不泄露答案。此机制为本轮待确认设计补充。

I06未通过的还原只给简短状态，允许继续补充；可以回看已公开内容，不列出玩家尚未发现的隐藏节点，不送出新线索。沿用现行不提前泄底契约
I07单人提示点击直接公开下一层固定提示，不投票；每题最多三层，按序发布，可回看。建议提示不扣问答次数，仅消耗一层。三层和单人直取已确认；不扣次数在本稿明确为建议
I08等待与计时有效回答等待和提示完整发布期间冻结。建议所有正式请求从受理到结果发布均冻结，覆盖范围识别、澄清、无效输入判断和失败等待；改写输入、看规则及阅读已发布消息继续计时。冻结扩展为本轮待确认设计补充D-A
I09冷场120秒无玩家提交问题、还原或获取提示时，只询问是否需要提示；不自动展开提示，同一次沉默不反复催促；系统消息、看规则和切换页面不重置玩家活跃时间。120秒与不自动泄提示沿用既定规则；单人活跃事件口径为本稿设计建议
I10时间或次数耗尽停止受理新请求，已受理的最后一个请求先落定；最后一次正式还原正确则判成功，否则按耗尽原因揭晓。无效／失败请求返还预留，不误判耗尽。已确认规则
I11主动揭晓与退出建议主动揭晓二次确认并进入复盘，单独记录结束原因；显式退出保留现场并记中断，不伪装成正常通关。主动揭晓为待确认D-B；中断与完成分开已确认
I12刷新、切后台和回来建议恢复同一局、问答、次数和草稿，时间按服务端经过继续流逝；不因切后台、刷新或短断线自动暂停或重置。系统正在处理的冻结区间仍按服务端结算。恢复和不重置已确认；离开仍计时为待确认D-C
I13重复与异常同一请求重发只执行和结算一次；超时、断网、非法格式或不可靠输出不冒充“否”，不扣游戏次数，不无限冻结；保留问题和重试入口。人工复核型内容缺口标为需核验，不临时补设定。既定原则；超时配置在实现阶段给出明确值并演练
I14可疑回答反馈玩家可定位一条消息反馈；保留原回答和处理轨迹。测试中确认关键答反、剧透或误判通关时阻断放行，不能静默改历史美化结果。既定验收原则
I15音乐保留个人音量／静音，使用可确认来源的预设纯音乐，不随推理猜测切换。无可用素材时显示未接入，音乐失败不阻断文字流程。已确认体验方向；素材接入状态需如实展示
I16揭晓与复盘固定汤底与固定因果解释先完整呈现；个性化复盘仅引用真实问答，明确优点与盲区。AI复盘失败时展示有标识的固定讲解降级，再完成收尾。既定方向；实际复盘模型尚未验收
“游戏剩余次数”“提示剩余层数”和“内部API调用额度”分别计数。一次游戏提问可能使用两次模型调用；提示与固定揭晓不需要临场生成。输入未明确、系统失败均不能伪装成有效四词回答。

这轮优先确认的 3 个补充

D-A · 待确认

所有系统处理等待是否暂停计时？

建议暂停，包括范围识别、最终判定、澄清和失败处理；玩家阅读、改写和查看规则照常计时。

受理时还不知道最终是不是有效问题，统一冻结可避免模型延迟或故障占用玩家推理时间。

D-B · 待确认

是否允许中途主动查看汤底？

建议允许；放在次级入口，二次确认后结束推理，仍进入揭晓与复盘，记录为主动揭晓。

卡关时有明确出口，避免误触或假装正常通关。

D-C · 待确认

刷新、切后台或短暂离开，是否继续计时？

建议保留本局并继续计时，回来恢复；系统处理中的暂停仍按服务端记录；显式退出记中断。

保持已有不重置规则，也为以后多人局共用计时逻辑。

其余新增布局与操作细节也属于本草案建议。确认方案后再开始制作；方案本身不代表已有实现或新增API调用授权。

SP06提示边界逐次点三层，再次点击；回看旧提示。固定原文、顺序和层数正确，无第四层临场生成；回看不重复消耗层数。程序功能测试，不需模型
SP07两段等待计时让范围识别和最终判定分别延迟，随后返回澄清或四词答案。整段受理等待只冻结一次，结果发布后恢复；玩家改写、读规则时继续走；按D-A最终确认执行。可控时钟与延迟注入
SP08最后一次边界仅余一次时提交正确还原；另测最后一次普通回答、无效输入和失败。正确还原优先成功；普通有效回答用尽则收尾；无效或失败返还预留。程序边界测试
SP09重复提交与恢复双击、重复请求ID、刷新、短断线再回来。不多扣次数、不重复调用；保留同一局记录与草稿；时间按D-C确认的规则恢复。程序功能与恢复测试

SP12复盘可追溯一局正常收尾；另模拟个性化复盘失败。贡献与判断可关联真实消息；不虚构玩家问过的问题；失败明确降级；收尾完成才标整局完成。整局记录核对＋故障注入
SP13冷场与声音持续静默、重新发问、三层提示已用尽；静音及播放失败。只询问不送提示，不重复催促；个人设置有效，声音失败不影响计时和提问。程序功能测试
SP14未揭晓数据边界检查游戏客户端页面资源、公开请求响应和错误信息。无完整汤底、私有事实／节点、提示词或Key；未公开提示不可从客户端预加载读出。资源与接口检查
SP15手机完整可操作小屏阅读长汤面、键盘弹起、长问答、还原草稿、结果返回。汤面可随时回看，当前输入与提交按钮可达，长文可滚动；不依赖悬停；误触不会直接泄底。手机与电脑人工走查

固定验收中出现关键事实答反、严重剧透、错误通关、额度计时错误或复盘捏造，必须先修复并回归。集合内通过不等于线上永远无错误，也不证明玩家愿意持续玩。

实施与验证顺序

  • 先用固定输出夹具检查页面、状态、计时、幂等、失败与收尾，不调用模型；夹具须标为模拟，不宣称AI验收。
  • 梳理原48条与原8条控制场景的迁移映射，保留失败和争议。
  • 方案确认并制作后，另锁定连续对话、还原和复盘实测材料，确认新增调用数，再调用真实模型。
  • 最后进行内部整局试玩与回放，按SP01—SP17记录实际证据。

模型与预算边界

正式问题候选采用公开范围识别＋必要的汤底判定；公开模块不收到隐藏资料，澄清使用白名单。正式还原始终按实际汤底与实际确认事实处理，不将假设问题结果当事实。提示和固定揭晓由程序读取已审原文；个性化复盘只读取本局固定事实与真实记录。

已累计162次，当前可用调用数为0；累计费用上限仍为5元。本轮方案整理不调用模型，不需要配置Key。真实模型联调前另行确认调用次数，并预留收尾成本，不重置已有账本。

完整提问现有候选结构可能串行调用两次模型，需要记录端到端等待与失败样本；实际体验门槛等原型测量后再评审。音乐素材状态和自动复盘降级必须如实显示。
