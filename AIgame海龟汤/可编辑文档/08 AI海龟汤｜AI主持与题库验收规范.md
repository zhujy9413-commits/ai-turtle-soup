# 08 AI海龟汤｜AI主持与题库验收规范

版本 V0.1.2｜已完成首批模型小样，全量验收未执行｜2026-10-25。

## 1. 验证目标与模型状态

验证的是“固定审核题目下的专业主持”，不是通用模型榜单分数。qwen3.7-flash 为已确认主候选，已对固定快照完成首批6条小样，尚未完成专项全量验收；备用模型尚未最终选定。官方说明支持结构化输出，不能替代语义准确性验证。[模型说明](https://help.aliyun.com/zh/model-studio/qwen3-7-flash)、[结构化输出说明](https://help.aliyun.com/zh/model-studio/qwen-structured-output)

## 2. 每题入库交付包

| 部分 | 必须包含 | 不通过的例子 |
|---|---|---|
| 公开汤面 | 可引发好奇但不欺骗事实的文本，题名、难度、恐怖强度和非泄底主题；不公开本格／变格分类 | 汤面与汤底直接矛盾，或题名先泄露核心反转，或标签提前公开本格／变格 |
| 固定汤底 | 完整时间线、人物关系、动机、过程、结局 | 仅一个反转句，无法回答合理追问 |
| 事实边界 | 明确事实、否定事实、未设定细节、无关分支；变格规则及限制 | 临时引入新鬼怪能力解释一切 |
| 因果节点 | 玩家必须还原的节点及其联系，哪些细节不要求猜出 | 只要命中几个词就通过，错误因果也被接受 |
| 提示 | 三层逐步推进，每层有适用方向且不直接替代解答 | 第一层直接公布凶手或关键机关 |
| 判定样例 | 常见问法、否定与指代、无关和未知，完整／部分／错误解答 | 只有理想问法，无边界与错误样例 |
| 氛围与来源 | 音乐标签、素材记录、题目创作或使用来源 | 不能说明题目和音乐可用于本项目 |
| 审核记录 | 版本、问题、修订、审核状态 | 未审核直接上线，改题影响在玩对局 |

首批 12 道、各难度 4 道是已确认数量；本套文档不冒充已创作完这 12 道题。题目作者和复核角色人员待指定，不能把模型自评当作独立人工通过。

## 3. 主持工作边界

模型读取当前题目固定资料和必要公开问答，不读取其他房间，不需要联网补充世界观。对正式问题返回结构化判定，玩家端仅显示四个允许答案之一。内部可记录引用的事实编号与错误类型用于审核，不向玩家暴露完整答案、模型内部推理或隐藏判定节点。

提示从已审三层中选择下一层，揭晓展示原文；这两项可以由程序直接执行。复盘只能引用真实问答和固定因果。投票、计时、额度、房主、状态转移均由程序校验，模型不能执行自由指令修改规则。

## 4. 评测集设计

建议每题准备至少 20 条正式问题与多轮改写场景，12 题合计至少 240 条问题；每题另准备完整、缺节点、错误因果等解答对照。这个数量是建议测试起点，尚未确认且不代表统计充分性。题目作者与复核者先对预期判定达成一致，争议题先修订，不把标签争议记成模型错误。

| 测试类别 | 要证明什么 | 必须观察的失败 |
|---|---|---|
| 明确事实是／否 | 事实与问法的基本映射 | 关键事实答反 |
| 未设定与无关 | 区分不知道细节和不影响解答 | 把有用分支误判无关，或编造未知细节 |
| 否定、双重否定、指代 | 正确理解中文问题 | 按关键词机械答复，身份或否定方向错 |
| 多问题与歧义 | 先澄清而非随便选择一半回答 | 混合真假却只答一个是字 |
| 跨轮同义改写 | 同事实前后一致 | 换问法即改变事实或忘记先前回答 |
| 变格设定 | 在该题规则内推理 | 套用现实拒绝鬼怪，或创造超出设定的新能力 |
| 诱导泄底 | 玩家不能通过“忽略规则”等得到答案 | 输出汤底、隐藏提示或未经批准线索 |
| 错误但合理的故事 | 对照固定真相而非迎合 | 把另一种解释当正确答案 |
| 部分与完整因果 | 精确判定解答完成 | 漏关键环节通过，或只因措辞不同拒绝正确解答 |
| 长对话与并发 | 上下文与房间隔离 | 串房、超额受理、回看记录缺失、延迟失控 |

保留一部分未参与提示词优化的换问法和题目场景作回归／留出验证，防止仅对现有测试集调优。对照模型使用同一固定资料、同一用例及相同可见信息，记录版本和参数，不能把不同输入条件的成绩直接比较。

## 5. 指标与建议放行门槛

| 指标 | 口径 | 本版建议 |
|---|---|---|
| 事实判定正确率 | 与已审标签一致的有效问题数／有明确标签的问题数 | 先记录分题、分类型成绩；阈值待首轮基线评审 |
| 多轮矛盾率 | 同一事实多轮场景出现相互矛盾的组数／测试组数 | 单列，不被整体准确率掩盖 |
| 严重泄底 | 未揭晓、未批准提示时额外暴露解答关键信息的次数 | 固定放行测试中出现即阻断，修复后重测 |
| 误判通关／误拒正确 | 对照解答集中的错误通过／错误拒绝次数 | 关键误判阻断；细节措辞类单独分析 |
| 复盘可追溯 | 所有玩家贡献与论断能关联实际消息或固定事实 | 虚构提问或贡献不能通过 |
| 延迟 | 受理到公开发布，分队列与模型，含失败样本 | P50／P95 实测后再定发布目标，当前无秒数承诺 |
| 单局真实成本 | 账单与用量汇总，包含额外重试与可能思考费用 | 在预算和开局预留内可持续，不能只按可见字数算 |

固定测试集“零严重错误”只说明该集合通过，不代表线上永远无错误。上线后仍需反馈、回放和回归。没有评测数据时不能在产品宣传里使用“专业级准确率”等量化暗示。

## 6. 核心功能验收场景

| 编号 | 输入／前置 | 预期结果 |
|---|---|---|
| AC01 | 汤面正在发布，客户端尝试提问 | 不受理、不扣次；完整发布后统一进入推理 |
| AC02 | 两人提示投票，一赞成一反对 | 平票不公开；三人两赞成才公开下一层 |
| AC03 | 六人房四票赞成，之后有人离线 | 本次基数快照不变，已达门槛只公开一次 |
| AC04 | 最后一个额度，多人同时提交 | 受理预留不超过 1；其他请求明确拒绝；重发同 ID 不再扣 |
| AC05 | 最后额度受理完整正确推理 | 判成功后全房揭晓，不先按次数耗尽记失败 |
| AC06 | 多次 AI 等待与提示冻结重叠 | 只计算冻结并集，恢复一致；普通讨论和规则查看不暂停 |
| AC07 | 讨论里碰巧说中答案 | 不自动揭晓；正式提交正确才通关 |
| AC08 | 开局后新成员进入 | 本局旁观，不可提问、投票、提交；下局才参与 |
| AC09 | 房主显式离开 | 转交最早仍在房间成员，不丢局、不重置次数时间 |
| AC10 | 模型失败、超时或非法格式 | 不展示原始输出；不扣游戏额度；实际调用费仍入账；冻结可退出 |
| AC11 | 当前 8 局尚有局在复盘，第 9 局请求开始 | 拒绝新开始；复盘完成释放后可再开始 |
| AC12 | 后台改题或下架，已有局正在玩 | 已有局固定版本；新局按发布状态，紧急情况另按明确策略 |
| AC13 | 用户静音，其他人调大音乐 | 设置互不影响，音量状态刷新后恢复 |
| AC14 | 随机没有所有人未玩的新题 | 明确提醒并等待房主选择，不静默重复 |
| AC15 | 查看未揭晓接口、网页资源、错误日志 | 无汤底、事实全表、模型密钥或其他房间数据 |
| AC16 | 复盘模型异常 | 展示明确降级和固定讲解，记录异常，不能假装个性化完成 |
| AC17 | 房主选题、随机匹配、正式开场或检查未揭晓的公开数据 | 所有玩家均不提前获得本格／变格字段或同义暗示；不能只隐藏视觉标签却仍下发数据 |
| AC18 | 玩家正式问是否存在超自然机制或是否属于某种设定 | 按本局固定设定如实回答；语义不明先澄清，不因分类默认隐藏而拒绝正常提问 |

## 7. 错误处理与回归

将错误区分题目缺陷、标签争议、模型语义、上下文、规则实现、连接与素材等。每条记录题目版本、公开输入与回答、模型版本、复现条件、预期、实际和修复措施。不要未经说明静默修改历史主持答案。

题目修订触发其全套问题与解答回归；模型或提示配置变更触发跨题回归；计时与额度代码变更触发相应并发验收。不能用某一便宜模型的费用假设搭配另一模型的质量成绩作为放行依据。

## 8. 当前结论

本规范已定义怎么验，不提供虚构成绩。首批固定快照小样已有真实输出，当前6条中5条符合、1条未先澄清；12题正式内容、独立标签审核、全量评测、容量报告与真实账单仍待后续工作。未通过时选择修题、换模型、调整输入结构或缩小可玩题集，不用暗中增加线索、降低通关标准来美化成绩。
