# 07 AI海龟汤｜产品需求文档PRD

版本 V0.1.1｜设计与研发审阅稿｜2026-10-23。

适用范围为中文移动网页邀请码免费内测版。已确认规则来自 00 D01～D23；需求承接 04 R01～R28。本文将规则落到界面、状态、权限和异常。标为“设计补充，待评审”的内容尚未获得逐项确认；本稿不代表已开发或获准上线。

## 1. 产品目标与边界

让 1～6 名玩家在无需真人主持的情况下围绕固定真相完成推理、揭晓与复盘。首批 50 账号，最多 8 局同时运行；12 道审核题；技术预算目标 ¥300／月。第一版保留单人和多人、公开和私密、邀请、搜索与匹配。

不实现付费、会员、广告、排行榜、语音、原生 App、多语言、玩家投稿和未审生成题。名称暂定，界面采用暗色档案风格，中文文字清晰优先。

## 2. 角色与权限

| 操作 | 房主 | 本局参与者 | 本局旁观者 | 后台运营 |
|---|---|---|---|---|
| 选题、改规则、开始 | 开局前可以 | 不可以 | 不可以 | 不以后台身份代替房主 |
| 邀请与踢出 | 可以 | 可分享已允许的邀请入口；无踢人权 | 无踢人权 | 后台封禁属于另外的安全管理 |
| 正式提问、提交推理 | 若也是参与者，可以 | 可以 | 不可以 | 不能后台窥题后参与本题 |
| 申请提示、投票 | 若在线参与，可以 | 在线参与可以 | 不可以 | 不参与投票 |
| 查看汤面、公开记录与提示 | 可以 | 可以 | 可以 | 按运营权限定位问题 |
| 揭晓前看汤底、事实清单 | 不可以 | 不可以 | 不可以 | 经授权的题目编辑／审核可以 |
| 维护题目及发布 | 不可以 | 不可以 | 不可以 | 可以，操作留痕 |

设计补充，待评审：旁观者在当前局只读讨论，避免场外泄底；观战上限建议每房 6 人，独立于 6 名参与席位，仍受总测试账号与服务容量约束。普通参与者分享私密房链接等同邀请，是否仅房主可分享待评审。

## 3. 页面与信息架构

| 页面 | 必要信息与操作 | 成功去向／空异常态 |
|---|---|---|
| 注册／登录 | 邀请资格、邮箱密码、登录、找回 | 成功进入教学／大厅；邀请无效、邮箱已用、验证码或邮件过期有明确反馈 |
| 新手教学 | 汤面／汤底区别、四种回答、正式问题和提交推理区别 | 可跳过；之后局内仍可查规则 |
| 大厅 | 创建、搜索公开房、快速匹配、输入房间码 | 无等待房时可创建或单人开始，不伪造对手 |
| 等待房 | 房态、公开／私密、成员、房主、题目公开信息、配置 | 无题或无符合条件新题提示；只有房主能开始 |
| 游戏 | 汤面、时间／次数、冻结与排队状态、推理记录、讨论、提示按钮、提交推理 | 手机分区切换有未读提示；规则与音量入口稳定可见 |
| 揭晓与复盘 | 结束原因、固定汤底、因果解释、复盘、反馈 | 复盘完成后返回原房间；失败走可理解降级 |
| 个人记录 | 已完成对局、结果、题目与复盘 | 无记录明确提示，不提前展示未揭晓答案 |
| 后台 | 题库、版本、分类难度、提示音乐、邀请码、反馈与用量 | 草稿／可测试／已上线／已下架清晰可区分 |

局内不展示模型名、Token 或提示词，避免干扰玩家决策；后台保留技术诊断。纯音乐使用用户授权操作后的播放入口，自动播放受限时不阻断游戏，不能假定网页能强制自动播放。

## 4. 房间与对局状态

房间是长期容器，一间房可以进行多局。对局状态建议为：等待 → 汤面展示 → 推理 → 结束结算 → 揭晓 → 复盘 → 已完成。全员离开、服务不可恢复等另记“中断”，不得记为正常完成。

| 状态 | 允许行为 | 转移条件 |
|---|---|---|
| 等待 | 加入、离开、邀请、选题、调规则 | 房主开始且题目、容量、预算检查通过 |
| 汤面展示 | 接收汤面、查看规则和声音设置 | 完整汤面发布后进入推理；失败不开始计时 |
| 推理 | 讨论、正式问题、提示与解答 | 正确提交，或有效时间／额度耗尽 |
| 结束结算 | 拒绝新问题与解答，完成已受理请求 | 所有受理结果落定，确定结束原因 |
| 揭晓 | 固定答案与因果说明 | 答案完整发布，进入复盘 |
| 复盘 | 阅读本局讲评、评价反馈 | 复盘结果完整呈现，系统标完成 |
| 已完成 | 保存、已玩标记、回等待房 | 房主重新选题再开局 |

8 局容量从开局预占起占用，直至复盘完成或对局中断才释放，不能在刚揭晓时提前释放。等待房不占“进行中对局”名额，等待房总数与空房清理时长为后台待定配置。

## 5. 核心规则 BR01～BR12

BR01 选题与开局。房主只看题名、难度、恐怖强度等公开元信息。本格／变格仅为主持与后台审核内部分类，不在选题、筛选、匹配、等待房或开场预告，房主与其他玩家一致。玩家正式询问相关设定时，主持按固定事实正常回答；不得用近义标签暗示分类。随机优先排除当前参与者已玩题，无新题先提醒，允许房主明确选择重复题。开始前复核成员与题目，固定本局题目版本、规则及参与名单；后台后续改题不影响本局真相。

BR02 规则配置。入门 15 分钟／25 次，进阶 25／40，硬核 40／60。开局前可调，最高 60 分钟／100 次；设计补充待评审：仅接受正整数分钟与次数，下限各 1；不提供无限值。所有参与者可查看最终规则，开局后锁定。

BR03 讨论与提问。讨论不调用主持，不扣额度，不触发解答判定。正式提问必须使用独立提交入口。问题与回答一一关联，有时间和发起者；只展示“是／否／无关／不清楚”。格式提示、系统故障提示和已批准提示使用不同消息类型，不伪装成四词回答。

BR04 回答含义。“是／否”对固定事实作真伪判定；“无关”表示该问题不影响关键解释；“不清楚”表示已审核设定未确定该事实且不能合理断言。否定问句和指代须按问题的明确语义判定，不用“不清楚”掩盖模型失败。复合、歧义或无法明确是非判定的提问请玩家改写，不额外泄露答案。

BR05 额度与受理顺序。正式有效回答扣一次；错误解答扣一次；正确解答直接触发成功。输入不合适与系统失败不扣游戏额度。服务器受理时预留一个可用额度，实际结果后结算或返还；已预留不能被其他并发请求重复使用。请求需唯一标识，重发不重复执行与扣次。界面区分剩余额度和处理中预留。

BR06 提交推理。玩家在独立入口写完整因果解释，提交前提醒可能消耗额度。不按关键词命中或相似度自动通关，检查预设的全部关键因果节点且没有与答案冲突的核心事实。错误只回复“尚未完整还原真相”。同一时间只处理一份推理；任何一人正确，全房结算揭晓。正常讨论中猜对不触发。

BR07 提示投票。每题三层，每次通过只公开下一层，已公开提示可回看、不再次扣层数。当前在线参与者为 1 人时直接获取；多人申请者自动赞成，以投票发起时在线参与者人数 N 为快照，通过门槛 floor(N/2)＋1。N＝2／3／4／5／6 时分别需 2／2／3／3／4 票。平票、未过半或 30 秒到期不通过；AI 不投票。投票中进入或离开不重算本次基数，下一次重新统计。同一时间仅一场提示投票。

BR08 计时。有效推理时间从完整汤面发布后开始。有效回答等待、提示生成和完整展示期间冻结；讨论、投票、阅读规则正常计时。以服务器计时为准，多次冻结取区间并集，不重复减时间；恢复后续计剩余时间。提示“展示完成”指内容发布完成，不等每个人点确认。设计补充待评审：为判断是否有效而发生的系统处理等待也不扣玩家时间，失败或格式处理结束后恢复，避免故障罚时。冻结不能无限等待服务恢复，需超时分支。

BR09 冷场。120 秒没有参与玩家提问或讨论，系统只询问是否需要提示，不自动公开、不代替申请投票。AI、系统、旁观消息不重置玩家活跃时间；提醒发出后本次沉默不重复催促，直到参与者再次发言。提示层数用尽时不诱导获取不存在的新提示。

BR10 结束边界。有效时间或可用额度用尽后停止受理新问题／推理，已有预留请求按顺序落定。最后一份受理推理若正确，优先记“成功”；否则按耗尽原因揭晓。不得因后台修改、讨论猜中或相似度进度条提前揭晓。队列不得超额预留；拒绝受理必须告知原因。

BR11 揭晓与复盘。展示审核汤底和关键因果，再结合真实记录说明突破和盲区。不得编造某玩家提过的问题或对错。复盘完整发布才标本局完成、释放容量并返回等待。反馈可稍后补充，不要求全员投评价才能结束。设计补充待评审：复盘生成失败时展示“自动复盘暂不可用”及固定因果讲解，记录降级后完成收尾，不冒充个性化复盘成功。

BR12 音乐。根据题目预设氛围，可同类复用；推理中不根据猜测切换。揭晓／复盘可平缓转收尾曲。音量静音按个人保存，不影响其他人、不暂停计时。曲目失效或播放被浏览器限制时提供状态与手动入口，不阻断问答。

## 6. 设计补充与异常处理，待评审

| 场景 | 建议响应 | 影响与待定项 |
|---|---|---|
| 原参与者短暂断线 | 以账号＋本局身份恢复同一记录，不因断线变成新旁观者 | 建议保留席位 120 秒，具体时长待评审；不凭断线重置时间额度 |
| 房主断线或离开 | 显式离开立即转交；重连不自动夺回房主 | 断线判离宽限待定，转交本身不停局 |
| 被踢后重新进入 | 提示已被移出，避免马上通过匹配回到同房 | 建议本局内禁止重入；跨局解除规则待评审 |
| 同一账号多端 | 恢复同一身份，操作幂等；不允许增加投票和多扣次数 | 同时参与多个进行中房间建议禁止，待评审 |
| 模型超时或格式异常 | 不展示原始输出，有限重试后提示系统暂未完成判定，释放预留与冻结 | 重试次数／超时秒数根据评测定；云端已产生费用仍记账 |
| 已发布主持答案疑似错误 | 允许针对该条反馈，运营复核并标明修正 | 是否局内暂停、返还额度及通知方式待评审；不得静默改历史 |
| 私密链接无效、房满或关闭 | 显示明确原因与回大厅入口 | 不泄露私密房列表或密码、邮箱 |
| 没有等待房可匹配 | 提供创建／单人入口，不承诺立即有真人 | 50 账号不保证在线供给 |
| 全员离开 | 停止后续调用，关闭房间，进行中局记中断 | 中断记录建议可定位而不计完成；保留期限待数据规则确认 |
| 预算不足或第 9 局 | 保留等待房，拒绝新开局，说明额度／容量原因 | 不挤占现有局的结尾预留，不自动购买或充值 |

## 7. 内容与数据需求

| 对象 | 必要字段 | 关键边界 |
|---|---|---|
| 题目版本 | 公开题名、非泄底主题、难度、恐怖强度、汤面；私有本格／变格分类、汤底、事实、因果节点、三层提示、通过标准、音乐、审校状态 | 公私字段分开；设定分类不进公开接口或隐藏页面字段；按局快照，不把全部题库发送前端 |
| 房间 | ID／邀请入口、可见性、房主、成员、房态与规则 | 私密不被搜索；房主不自动获得审核权限 |
| 对局 | 本局题目版本、参与者、状态、起止、结束原因、额度与冻结记录 | 已完成与中断分开，所有权与可见范围需明确 |
| 消息与请求 | 作者、类型、问题关联、幂等 ID、受理与完成时间、结算状态 | 讨论、问题、系统、提示和复盘分开；不输出内部依据或模型思考 |
| 提示投票 | 发起者、基数快照、投票者、票数、到期、层数与结果 | 同账号只有一票，旁观不可投，平票无提示 |
| 模型用量 | 模型版本、输入输出计量、失败／重试、实际计费与对局关联 | 不收集不必要个人信息，不在诊断日志明文保存凭据 |
| 反馈 | 关联题目版本／问答、问题类型、处理状态、修复记录 | 可追溯，不让普通玩家看到后台汤底与其他人私密信息 |

设计补充待评审：个人历史优先仅本人可见，原局参与者可查本局公开记录；不把完整回顾做成默认公开广场。数据保存期限、导出和注销后的处理需发布前确定，不能擅自永久保留。

## 8. 后台与发布规则

草稿 → 可测试 → 已上线 → 已下架。进入可测试前应完成内容字段与固定真相检查；进入已上线前应通过模型回归与素材、发布要求。发布动作记录操作者、版本和时间；修订新版本不改当前局。下架阻止新选题，正在进行的局使用固定快照；紧急安全下架的中断与通知策略待评审。

后台最小功能包括题目编辑、标签难度、关键因果与提示、音乐关联、审校记录、邀请码、反馈、费用与容量查看。无需建设复杂 CMS 或自动生成整套题库。

## 9. 非功能与安全验收

8 个对局并发测试必须覆盖各 6 名参与者的问答、投票、计时与收尾同步，不能只打开 8 个空房。网页刷新、重复请求、断网重连不重扣额度、不重置计时。超过容量友好拒绝。

模型延迟记录端到端 P50／P95：从服务端受理到公开回答发布，队列等待、模型时间与失败另列；不删除超时样本美化结果。具体可接受时延与错误率门槛待实测后评审，当前不承诺秒数。

揭晓前，普通客户端接口、页面资源、消息推送及错误信息不得包含私有汤底、事实全表、通关规则或密钥。服务端校验角色、状态和输入，不信任客户端倒计时、票数和次数。公开消息作安全转义与必要内容治理；运营日志和模型输入避免无必要的邮箱等身份信息。

未完成服务适用性、实名与未成年人、素材和数据规则核验，不将“可运行”标为“可对外上线”。邮箱是已确认登录方式，不等于已满足可能适用的实名要求，见 09。
